# Noutify Phase 0 — Setup instructions for coding agents

Use this procedure to configure Noutify for a target repository. This is an
operational contract, not general background. Read `NOUTIFY_CONTEXT.md` before
changing Noutify itself.

## Scope

This procedure supports only:

- Windows;
- Node.js 24 or newer;
- Claude Code;
- ntfy;
- the `WAITING` event generated by Claude Code's `Stop` hook.

Do not claim support for other agents, providers or operating systems.

## Safety rules

1. Detect the environment before changing files.
2. Never overwrite `.claude/settings.local.json`.
3. Never remove or edit hooks that Noutify does not own.
4. Never commit `.noutify.local.json`.
5. Treat the ntfy topic as a secret.
6. Do not repeat the topic in chat, reports, documentation or persistent logs.
7. Never read a Claude transcript for notification content.
8. Do not mark setup complete until the user confirms phone receipt.
9. A failed notification is not a blocker for the agent's main task.
10. Stop and explain any malformed existing Claude settings; do not repair them
    by replacement.

## Procedure

### 1. Preflight

Verify:

```powershell
node --version
npm --version
```

Require Node.js 24 or newer. Confirm the target path with the user when more than
one repository is plausible.

### 2. Build Noutify

From the Noutify source directory:

```powershell
npm install
npm test
npm run typecheck
npm run build
```

Do not proceed if tests, type checking or build fail.

### 3. Install into the target project

Run setup with an absolute target path:

```powershell
$NOUTIFY_ROOT = (Resolve-Path .).Path
$TARGET_ROOT = 'D:\path\to\target-project'
node "$NOUTIFY_ROOT\dist\cli.js" setup --project "$TARGET_ROOT"
```

The command creates public and private configuration, adds the private filename
to `.gitignore`, and merges one project-local Claude `Stop` hook.

The generated topic may appear in the local terminal during the first setup.
Do not copy it into the conversation. Ask the user to read it from their local
terminal and keep it private.

### 4. Guide mobile subscription

Give the user the official ntfy phone guide:

<https://docs.ntfy.sh/subscribe/phone/>

Ask the user to:

1. install and open ntfy;
2. add a subscription;
3. enter the configured server;
4. enter the topic displayed locally by setup;
5. report when the subscription is ready.

Wait for the user before sending the test.

### 5. Send the test

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" test --project "$TARGET_ROOT"
```

Ask exactly whether the phone received the “Noutify connected” notification.

If it did not arrive:

- do not run `confirm`;
- verify the app subscription, server and local config without printing the
  topic;
- retry only when the user asks;
- report failure without exposing private values.

### 6. Confirm receipt

Only after an explicit positive answer:

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" confirm --project "$TARGET_ROOT"
```

### 7. Diagnose

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" doctor --project "$TARGET_ROOT"
```

All four checks must pass:

- configuration;
- private ignore rule;
- Claude Stop hook;
- phone confirmation.

### 8. Acceptance

The final manual gate is a later Claude Code turn:

1. allow Claude to finish a response;
2. verify that the phone receives “Agent waiting”;
3. verify that the message says only that the agent is waiting;
4. verify that it does not claim the task was completed.

Until those steps occur on a real phone, report the software implementation as
verified but the real-device acceptance as pending.

## Uninstall

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" uninstall --project "$TARGET_ROOT"
```

This removes only the exact Noutify hook command and preserves configuration.
Never delete the user's other Claude hooks.
