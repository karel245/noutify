# Noutify agent-guided setup

This file is an operational contract for Claude Code. Follow it in order when a
user asks you to install Noutify. Do not make the user type paths or commands
that you can determine and run safely yourself.

## Trigger

The normal installation starts with this single user prompt from the target
project root:

```text
Install Noutify following Noutify/SETUP.md.
```

## Supported environment

This procedure supports only:

- Windows;
- Node.js 24 or newer;
- Claude Code with project-local hooks;
- ntfy;
- the `WAITING` event generated by Claude Code's `Stop` hook.

Do not claim support for other operating systems, agents, providers or events.

## Interaction language

Choose the language used for every explanation and question in this order:

1. Use the language of the user's latest clear user request or established conversation.
2. If that is inconclusive, inspect the operating-system UI locale with
   `[System.Globalization.CultureInfo]::CurrentUICulture`.
3. If that is also inconclusive, use English.

The user may override this choice at any time. Translate explanations naturally.
Keep commands, paths, filenames, configuration keys and literal program output
unchanged.

## Non-negotiable safety rules

1. Detect and validate the environment before changing the target project.
2. Never overwrite `.claude/settings.local.json`.
3. Never remove or edit Claude hooks that Noutify does not own.
4. Never commit `.noutify.local.json`.
5. Treat the ntfy topic as a secret. Never repeat the topic in conversation,
   summaries, documentation, commits, issues, or agent-authored logs.
6. Never read a Claude transcript for notification content.
7. Do not mark setup complete until the user confirms phone receipt.
8. Do not run `confirm` until the user explicitly confirms that the test arrived.
9. A failed notification must never block the coding agent's main task.
10. Stop and explain malformed existing Claude settings. Never repair them by
    replacing the file.
11. Keep `Noutify/` at the same path after setup because the installed hook uses
    its absolute compiled-runtime path.

## Installation procedure

### 1. Locate Noutify and the target project

The expected layout is `<target-project>/Noutify/SETUP.md`. From the target
project root, resolve both directories without asking the user to type them:

```powershell
$NOUTIFY_ROOT = (Resolve-Path 'Noutify').Path
$TARGET_ROOT = (Resolve-Path (Split-Path -Parent $NOUTIFY_ROOT)).Path
```

Verify the installation source before continuing:

```powershell
$requiredFiles = @('SETUP.md', 'package.json', 'package-lock.json', 'src\cli.ts')
$missingFiles = $requiredFiles | Where-Object {
  -not (Test-Path (Join-Path $NOUTIFY_ROOT $_))
}
if ($missingFiles) {
  throw "Noutify source is incomplete: $($missingFiles -join ', ')"
}
```

Confirm that `$TARGET_ROOT` is the parent of `$NOUTIFY_ROOT`. If the layout is
missing or ambiguous, stop and ask the user to identify the intended target.
Do not guess another directory.

### 2. Run preflight checks

Run:

```powershell
node --version
npm --version
$nodeMajor = [int]((node --version).TrimStart('v').Split('.')[0])
if ($nodeMajor -lt 24) { throw 'Noutify requires Node.js 24 or newer.' }
```

Stop before modifying the target project if Windows, Node.js 24+ or npm is not
available. Explain the missing prerequisite in the selected interaction
language.

### 3. Prepare the Noutify runtime

Run every validation from the project-local `Noutify/` directory:

```powershell
Set-Location $NOUTIFY_ROOT
npm ci
npm test
npm run typecheck
npm run build
```

Do not continue if dependency installation, tests, type checking or build fails.
Report the failing stage in the selected interaction language.

### 4. Configure the target project

Run:

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" setup --project "$TARGET_ROOT"
```

This creates public and private configuration, adds the private filename to the
target `.gitignore`, and merges exactly one project-local Claude `Stop` hook.
Existing unrelated hooks must remain intact.

On the first setup, the command displays the generated topic in the local
terminal. Do not quote, summarize or otherwise reproduce that value. Tell the
user to read it directly from the local terminal and keep it private.

### 5. Guide the phone subscription

In the selected interaction language, ask the user to:

1. install and open ntfy using <https://docs.ntfy.sh/subscribe/phone/>;
2. add a subscription;
3. use `https://ntfy.sh` unless they deliberately configured another server;
4. enter the topic displayed locally by setup exactly as shown;
5. tell you when the subscription is ready.

Pause here. Do not send the test until the user says the subscription is ready.

### 6. Send the test

After the user says the subscription is ready, run:

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" test --project "$TARGET_ROOT"
```

Ask whether the phone received the `Noutify connected` notification, then pause
for the answer.

If it did not arrive:

- Do not run `confirm`.
- Check the app subscription, configured server and local configuration without
  printing the topic.
- Retry only when the user asks.
- Report the failure without exposing private values.

### 7. Confirm receipt

Only after the user explicitly confirms that `Noutify connected` arrived, run:

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" confirm --project "$TARGET_ROOT"
```

Never infer receipt from a successful HTTP request or CLI exit code. The phone
owner's explicit confirmation is the acceptance signal.

### 8. Run diagnostics

Run:

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" doctor --project "$TARGET_ROOT"
```

Require all four checks to pass:

- configuration;
- private ignore rule;
- Claude Stop hook;
- phone confirmation.

Explain any failing check in the selected interaction language without exposing
private values.

### 9. Complete real-agent acceptance

Guide the user through a later Claude Code turn:

1. allow Claude to finish a response in the configured target project;
2. verify that the phone receives `Agent waiting`;
3. verify that the message says only that the agent is waiting;
4. verify that it does not claim that the task was completed.

Until this occurs on a real phone, describe the local installation as verified
and the real-device acceptance as pending.

## Existing installation behavior

Setup is idempotent. If Noutify is already configured, the command preserves the
existing topic and ensures the exact Stop hook is present once. Run `doctor` to
determine the current stage. If phone confirmation is still pending, guide the
user to read the existing topic locally from `.noutify.local.json`; never print
or repeat it yourself.

## Uninstall

When the user explicitly asks to uninstall Noutify, run:

```powershell
node "$NOUTIFY_ROOT\dist\cli.js" uninstall --project "$TARGET_ROOT"
```

This removes only the exact Noutify hook and preserves configuration. Never
delete other Claude hooks or the user's configuration automatically.
